# UI Update Handoff

This guide describes the dashboard and prototype changes in commit `0cdc963` (`UI UPDATE`) on `main`, dated November 20, 2026. It is intended to help a teammate review the update and run it locally.

## What changed

- Refreshed the staff dashboard shell, navigation, shared styles, and dashboard overview.
- Reworked the activity logs, alerts, and bookings screens, with updates to fleet, driver, and staff pages.
- Expanded the standalone dashboard prototype in `prototype/`.
- Added browser-local demo records and demo-only delete controls, and updated supporting auth, API, table, and fleet snapshot code.

The React app routes are `/` (dashboard), `/vehicles`, `/bookings`, `/drivers`, `/staff`, `/notifications` (alerts), and `/logs` (activity logs). `src/App.js` defines these routes. The older scaffold under `web/g_fleet_web` is not the active frontend; see [README.md](../README.md).

## Try the standalone prototype

The prototype is a local, self-contained preview with sample data. It does not call Supabase or the API and does not need internet access.

1. Install Node.js and npm if they are not already available.
2. From the repository root, run:

   ```sh
   npm run prototype
   ```

3. Open [http://127.0.0.1:4173/prototype/index.html](http://127.0.0.1:4173/prototype/index.html).

The preview server listens on `127.0.0.1`. If port `4173` is occupied, set `PORT` to a free port before starting it.

## Run the React dashboard with demo data

In development, the React app automatically uses demo mode, so Supabase credentials and the API server are not needed to explore the UI.

```sh
npm ci
npm start
```

Open [http://localhost:3000](http://localhost:3000). Look for the **DEMO DATA** badge to confirm the dashboard is showing sample data. Changes are stored in this browser's local storage; use **Reset demo** in the navigation bar to restore the seeded sample records. Demo data is for review only and should not be treated as customer or operational data.

## Use live Supabase-backed data

Follow the setup and security instructions in [README.md](../README.md) and [the Phase 1.5 security model](PHASE_1_5_SECURITY_MODEL.md). Live mode requires the documented environment configuration, API server, and authorized linked profile. Do not put a Supabase secret or `service_role` key in frontend configuration.
